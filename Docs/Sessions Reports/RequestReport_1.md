# المطلوب: تقارير تفصيلية لنظام Habbak ERP

أنا مطور نظام **Habbak ERP** — نظام إدارة موارد مؤسسة لسلسلة محلات قهوة، مبني على:
- **Backend**: .NET 10 مع Clean Architecture (Domain / Application / Infrastructure / API)
- **Patterns**: MediatR (CQRS)، FluentValidation، EF Core Code-First
- **Database**: SQL Server + LocalDB
- **Frontend**: React + TypeScript مع دعم كامل للعربي والإنجليزي (RTL)

### 📄 التقرير الأول: `01-System-Overview.md`

**تقرير تفصيلي للسيستم بشكل عام والـ Options الموجودة فيه كـ Structure عام**

يجب أن يحتوي على:

1. **نبذة عامة عن النظام**
   - الهدف من النظام
   - الموديولات المخطط لها
   - المعمارية العامة (Clean Architecture)

2. **الهيكل التنظيمي للسيستم**
   - الشركات (Companies)
   - الفروع (Branches)
   - المستخدمين (Users)
   - الصلاحيات (Permissions — على مستوى الشاشة والحقل)

3. **البنية التحتية المشتركة**
   - MenuItems / FieldLabels (القائمة الديناميكية)
   - CodingRule (قواعد الترقيم)
   - Audit Trail (سجل التعديلات)
   - RowVersion (Concurrency)
   - IsDeleted (Soft Delete)
   - Multi-Company Support

4. **الموديولات والحالة الحالية**
   - ✅ مكتمل ومُختبر: الحسابات العامة
   - ✅ مكتمل ومُختبر: المخازن والتصنيع
   - ✅ مكتمل برمجيًا (بانتظار اختبار): المشتريات
   - 📅 مخطط له: المبيعات، POS، ETA، التقارير، الصيانة

5. **الـ Options العامة على مستوى السيستم**
   - فتح أكثر من شاشة في تاب
   - المرفقات (Attachment)
   - الطباعة والتصدير
   - الاستيراد مع Template

6. **الـ API Controllers الموجودة**
   - قائمة بكل Controller والوظائف الرئيسية

### 📄 التقرير الثاني: `02-Accounting-Module.md`

**تقرير تفصيلي بموديول الحسابات العامة (مكتمل ومُختبر)**

يجب أن يحتوي على:

1. **نظرة عامة على الموديول**
   - الهدف
   - عدد الشاشات
   - عدد قواعد العمل
   - عدد Controllers
   - حالة الاختبار: ✅ مُختبر

2. **الكيانات (Entities)**
   - دليل الحسابات (Account)
   - مراكز التكلفة (CostCenter)
   - القيود اليومية (JournalEntry)
   - السندات (Voucher)
   - العهد (CustodyRegister)
   - المطابقات (CashReconciliation / BankReconciliation)
   - الفترات المالية (AccountingPeriod)

3. **الشاشات (Screens)**
   لكل شاشة:
   - الاسم
   - النوع (List / Edit / Custom)
   - الحقول الرئيسية
   - الأزرار والإجراءات
   - القيود والصلاحيات
   - العلاقات مع شاشات أخرى

4. **التقارير (Reports)**
   - قائمة بالتقارير الموجودة
   - قائمة بالتقارير المطلوبة (ميزان المراجعة، دفتر اليومية، دفتر الأستاذ، الميزانية العمومية، قائمة الدخل)

5. **الدورة المستندية (Document Cycle)**
   - من إنشاء القيد → الترحيل → العكس
   - سير عمل السندات
   - دورة العهد والمطابقات
   - دورة إقفال الفترات المالية

6. **قواعد العمل (Business Rules)**
   - قائمة بكل قواعد العمل في الموديول

7. **الـ API**
   - قائمة بكل Controllers والـ Endpoints

### 📄 التقرير الرابع: `04-Purchasing-Module.md`

**تقرير تفصيلي بموديول المشتريات**

⚠️ **ملاحظة هامة**: هذا الموديول **مكتمل من ناحية التطوير** لكن **لم يتم اختباره بعد** من قِبل فريق الـ QA.

عند كتابة التقرير:
- اذكر كل ما هو موجود فعلاً في الكود.
- ضع علامة ⚠️ على أي جزء تشك في أنه يحتاج مراجعة أو اختبار.
- أضف قسم في نهاية التقرير اسمه **"البنود التي تحتاج اختبار"** واذكر فيه:
  - الشاشات التي لم تُختبر.
  - الـ Endpoints التي لم تُختبر.
  - دورات العمل التي تحتاج اختبار متكامل (End-to-End).

هيكل التقرير:

1. **نظرة عامة** (مع حالة الاختبار: ⚠️ مكتمل برمجيًا، بانتظار الاختبار)
2. **دورة المشتريات القابلة للتخصيص**
   - الأنماط الخمسة (Full / Direct / OrderBased / RequestBased / Simplified)
   - إعدادات دورة المشتريات
3. **الكيانات** (Supplier, PurchaseRequest, RFQ, PurchaseOrder, PurchaseInvoice, GoodsReceipt, PurchaseReturn, PurchaseExpense, SupplierPriceHistory, SupplierContract)
4. **التكامل بين المستندات**
   - Auto-Copy من مستند لمستند
   - SourceDocumentType / SourceDocumentId
5. **الشاشات** (13 شاشة)
6. **التقارير** (المشتريات حسب المورد/الصنف، أوامر شراء مفتوحة، فواتير غير مدفوعة، مردودات، تحليل أسعار، تقييم أداء الموردين)
7. **الدورة المستندية**:
   - من طلب الشراء → عروض الأسعار → أمر الشراء → الاستلام → الفاتورة → السداد
   - دورة المردودات
8. **قواعد العمل** (20 قاعدة)
9. **نظام الموافقات** (Approval Workflow)
10. **الـ API**
11. **البنود التي تحتاج اختبار** (جديد)

## ⚠️ ملاحظات هامة

1. **الالتزام بالمعلومات الموجودة فعلاً** في الكود — لو مش متأكد من حاجة، اكتب "TBD" واذكرها في قسم "Questions".
2. **لا تفترض** أي حاجة مش موجودة — استخدم الكود الفعلي كمصدر وحيد للحقيقة.
3. **اذكر الملفات والمسارات** لكل جزء (مثال: `src/Habbak.ERP.Domain/Entities/Account.cs`).
4. **اذكر الـ Controllers والـ Endpoints** الفعلية.
5. **اذكر الـ Migrations** والفروق بين النسخ.
6. **حالة الاختبار**:
   - الموديولات المُختبرة: الحسابات العامة، المخازن والتصنيع
   - الموديولات المكتملة برمجيًا فقط (بدون اختبار): المشتريات
   - في كل تقرير، وضّح حالة الموديول (مُختبر / غير مُختبر) في المقدمة.
7. **عند وجود أي شك في سلوك**:
   - اكتب التعليق `// TODO: Verify` في التقرير.
   - ضع البند في قسم "البنود التي تحتاج اختبار".
