## 2. الدورات المستندية

### 2.1 الوردية
```
مفتوحة (Open) ──Close──► بانتظار اعتماد الإقفال ──Approve──► مقفولة
                          [لو الفرق > الحد]
```
- `Rejected` **غير قابل للوصول بالتصميم** — مفيش `RejectShiftClose`.
- **فهرس فريد مفلتر** على `POSTerminalId WHERE Status = Open` بيمنع ورديتين مفتوحتين على نفس الجهاز.

**معادلة النقدية المتوقعة** (قاعدة 6) — منفَّذة حرفيًا:
```
المتوقع = الافتتاحي + مبيعات نقدية − إيداعات معتمدة − سحوبات معتمدة − مصروفات الدرج
```
> **الإيداع والسحب الاتنين بيطرحوا** — الاتنين بيمثلوا خروج نقدية فعلي من الدرج.
> والحركة **غير المعتمدة** بتساوي صفر في المعادلة.

### 2.2 الشيك — قلب الموديول
```
مفتوح (Open) ⇄ معلّق (Held)
     │
     ├── AddCheckLine / RemoveCheckLine / ChangeCheckOrderType
     ├── ApplyManualDiscount / RemoveManualDiscount
     ├── SetCheckCustomer / SetLoyaltyPointsRedemption
     ├── FireCheckLinesToKitchen
     ├── MergeChecks ──► مدمج (Merged)
     │
     └── CompleteCheckPayment ──► مكتمل (Completed)
                              ↘ ملغي (Cancelled)
```
- شيك الصالة **لازم يرتبط بطرابيزة**؛ التيك أواي/الدليفري standalone.
- البند اللي **اتبعت للمطبخ** حذفه بيتطلب **سبب إلغاء**.

### 2.3 إتمام الدفع — أكتر عملية معقدة في النظام

بالترتيب:
1. التحقق من حالة الشيك ووجود بنود
2. التحقق من مخزن الجهاز (`POS-TERMINAL-NO-WAREHOUSE`)
3. حساب الخصم اليدوي ← **ثم** استبدال النقاط (الترتيب مهم)
4. **`CheckTotalsCalculator`** 🆕 — رسم الخدمة والضريبة والإجمالي
5. التحقق إن مجموع الدفعات **يساوي الإجمالي بالظبط**
6. 🆕 التحقق من **وجود طرق الدفع** (G-9)
7. تجهيز الدفعات: تقريب نقدي + الباقي + التحقق من كفاية المدفوع
8. إنشاء `POSInvoice` **`Posted` مباشرة** + حفظ أول (للحصول على الـId)
9. خصم نقاط الولاء وكتابة `LoyaltyTransaction`
10. 🆕 **بناء خطة الاستهلاك** + **فحص نقص المكونات** + تطبيق الحركات
11. 🆕 **تجميد تكلفة البيع** على سطور الفاتورة
12. إنشاء `POSPayment` لكل دفعة، وتحويل الشيك لـ`Completed`، وتحرير الطرابيزة

> **الضريبة بتتحسب على صافي البنود بعد الخصم بس** — مش على رسم الخدمة ولا البقشيش.

### 2.4 حركة الدرج
```
مسجّلة (Recorded) ──Approve──► معتمدة   ↘ مرفوضة
```
**`DrawerExpense` مالهاش اعتماد إطلاقًا** — بتُسجَّل مرة وبتتحسب فورًا.

### 2.5 تذكرة QR
```
نشطة (Active) ──Redeem──► مستبدَلة (Redeemed)
```
**ذاتية الاحتواء**: الأصناف والكميات والأسعار متسجّلة عليها **وقت الإصدار**، فبتشتغل حتى لو
السعر اتغيّر بعدها. بتتولد من **استشاري التصنيع** (خلطات البن بالوزن) أو يدويًا.

## 3. استهلاك الوصفات (G-1 و G-2 — اتقفلوا)

### المشكلة الأصلية
```csharp
if (!item.IsStocked) { continue; }   // اللاتيه بيخرج من هنا
```
المنتجات التامة كلها `IsStocked = false`، و**مفيش أي منطق وصفات في طبقة POS إطلاقًا**.
النتيجة: بيعة بـ50.40 ج.م، **صفر حركة مخزنية**.

### الحل — قاعدة 17 (أولوية النموذج)
```
صنف > نقطة بيع > فرع > شركة  →  الافتراضي: Stocked
```

| النموذج | السلوك |
|---|---|
| **لحظي + وصفة معتمدة** | يستهلك **المكوّنات** (`ProductionIssue`) مقيسة بالكمية المباعة |
| **مخزني** (أو لحظي بلا وصفة) | يخصم **الصنف نفسه** (`POSSale`) |

**قاعدة 18** — اللحظي **بيمنع البيع** لو أي مكوّن ناقص، والفحص:
- **قبل أي خصم** (مفيش استهلاك جزئي)
- **مجمّع على مستوى الشيك كله** (لاتيه + كابتشينو بياخدوا من نفس اللبن)
- **بيسمّي المكوّن الناقص**: `لبن (متاح 7700 / مطلوب 9000)`

> ⚠️ **الافتراضي `Stocked` عن قصد** — التفعيل قرار إداري لأنه بيغيّر أثر البيع على المخزون
> و**ممكن يبدأ يرفض مبيعات**.

### تكلفة البيع (قاعدة 42)
تكلفة سطر اللاتيه = **مجموع المكوّنات**، مش تكلفة اللاتيه نفسه (اللي صفر لأنه مش مخزَّن):
```
9 جم بن × 0.50  = 4.50
150 مل لبن × 0.02 = 3.00
                  ─────
                  = 7.50
```

## 4. إعدادات الفرع — 11 مفتاح

`TipsEnabled` · `ServiceChargeEnabled` + `Rate` · `AllowSplitPayment` ·
`LoyaltyRedemptionEnabledAtPOS` · `ETAReceiptEnabled` · `CashRoundingIncrement` ·
`MaxAllowedShiftCashDifference` · `VatEnabled` + `VatRate` · `OperationMode`

> ⚠️ **الـendpoint Upsert كامل** — لازم `GET` قبل أي `PUT`، وإلا باقي المفاتيح هتتصفّر.

**تفاصيل دقيقة**:
- `AllowSplitPayment` بيتحكم **بس** في إن دفعتين يشاركوا **نفس** طريقة الدفع. خلط طرق **مختلفة** مسموح دايمًا.
- **التقريب النقدي إعلامي بحت** — `POSPayment.Amount` دايمًا المساهمة الدقيقة في الإجمالي.
- مفيش `PaymentMethod.IsCash` — **وجود `AmountTendered`** هو إشارة الكاش.
