## 1. الكيانات

| الكيان | الدور |
|---|---|
| `Customer` | العميل — رصيد نقاط الولاء عليه |
| `LoyaltyTier` / `LoyaltyProgramSettings` | شرائح الولاء وإعداداته (`PointsEarnRate`, `PointsRedemptionValue`) |
| `LoyaltyTransaction` | حركة النقاط — **الاستبدال بس هو اللي بيكتب فيها حاليًا** |
| `PriceList` / `PriceListLine` | قوائم الأسعار — سعر صالة/تيك أواي/دليفري لكل صنف |
| `Discount` | الخصومات |

| `SalesQuote` → `SalesOrder` → `SalesInvoice` | الدورة الأساسية |

| `SalesReturn` / `SalesReturnLine` | مرتجع المبيعات |

> فجوة**، وماينفعش يتبني إلا لو طلبه تاني.

## 2. الدورة الكاملة

```
عرض سعر ──► أمر بيع ──► فاتورة بيع ──► أمر تسليم [المخزون بيخرج هنا]
                                   ↘ مرتجع مبيعات [المخزون بيرجع]
```

### 2.1 عرض السعر
```
مسودة ──Submit──► مُرسل ──Accept──► مقبول ──► محوَّل (Converted)
                        ↘ مرفوض  ↘ منتهي (Expired)
```

### 2.2 أمر البيع
```
مسودة ──Confirm──► مؤكد ──► مُسلَّم جزئيًا ──► مُسلَّم ──► مفوتر
                        ↘ مرفوض  ↘ ملغي
```
`PartiallyDelivered` / `Delivered` **بيتحسبوا تلقائيًا** عند ترحيل أمر التسليم، بتحديث
`DeliveredQuantity` على كل سطر.

### 2.3 فاتورة البيع
```
مسودة ──► بانتظار الاعتماد ──Post──► مرحّلة
                                  ↘ مرفوضة  ↘ ملغاة
```

**الترحيل**:
- ❌ **مفيش قيد محاسبي**
- ❌ **مفيش حركة مخزون** — دي مسؤولية أمر التسليم

> ⚠️ **`SalesInvoice` مالهاش `WarehouseId` ولا حقل عملة** — كل مستندات المبيعات **أحادية العملة**
> ضمنيًا، على عكس المشتريات. وده سبب حارس العملة في سند القبض.

### 2.4 أمر التسليم — **هنا المخزون بيخرج**
```
مسودة ──PostDeliveryOrder──► مرحّل ↘ مرفوض
```

**الترحيل بيعمل**:
- خروج مخزني (`TransactionType.SalesDelivery`) من `DeliveryOrder.WarehouseId`
- تحديث `DeliveredQuantity` على أمر البيع وإعادة حساب حالته
- 🆕 **تجميد تكلفة البيع** على سطر الفاتورة المرتبطة (قاعدة 42)

### 2.5 مرتجع المبيعات
```
مسودة ──PostSalesReturn──► مرحّل ↘ مرفوض ↘ ملغي
```
دخول مخزني (`TransactionType.SalesReturn`)، والتكلفة بتتحل عبر `ResolveInboundCostAsync`.

## 3. تجميد تكلفة البيع (قاعدة 42 — جديد)

`SalesInvoiceLine.UnitCost` **اختياري (nullable)** — وده مقصود.

المواصفة بتقول Snapshot "لحظة **إنشاء السطر**"، بس ده **مستحيل هنا**: `SalesInvoice` **مالهاش
`WarehouseId`**، والمخزون بيخرج أصلًا عند **أمر التسليم** مش الفاتورة.

**فالتنفيذ بيجمّد التكلفة عند ترحيل أمر التسليم** — أول لحظة فيها مخزن معروف وبضاعة خرجت فعلًا.

> `UnitCost = null` معناها **لسه مفيش تسليم**، وبالتالي **مفيش تكلفة بيع تتقيّد أصلًا**.

---

## 4. فجوة معروفة مفتوحة بقرار

`SalesCycleSettings.RequiresSeparateDeliveryDocument = false` (نمط "فاتورة فقط") المفروض يخلي
**الفاتورة نفسها تخصم المخزون** (قاعدة 18) — **بس ده مش منفَّذ**.

**السبب**: محتاج `WarehouseId` على `SalesInvoice`، والنمط المستخدم والمختبَر فعليًا هو النمط
**الكامل** اللي بيستخدم أمر التسليم. اتساب مفتوح عن قصد.

## 5. نقاط الولاء — نصف مبني عن قصد

| الجزء | الحالة |
|---|---|
| **الاستبدال** (قاعدة 12) | ✅ مبني ومختبَر — بينقص `Customer.LoyaltyPointsBalance` فورًا ويكتب `LoyaltyTransaction` |
| **الكسب** (قاعدة 11) | ❌ **غير مبني إطلاقًا** — مفيش كود بيزوّد الرصيد |
| **إعادة حساب الشرائح** (قاعدة 13) | ❌ غير مبني |

> رصيد العميل **مبيوصلش لقيمة موجبة إلا بتعديل مباشر في قاعدة البيانات** — ده **خط نطاق مرسوم
> عن قصد**، مش نسيان. بناء الكسب كان هيتطلب لمس `SalesInvoice` وترحيلها، وده أكبر بكتير من نطاق
> المراجعة اللي طلبها العميل.
