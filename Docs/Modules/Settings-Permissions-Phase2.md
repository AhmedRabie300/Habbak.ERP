## 2. تسجيل الدخول والجلسات

| Endpoint | الوظيفة |
|---|---|
| `POST /api/v1/auth/login` | اسم مستخدم + كلمة مرور ← access token (JWT) + refresh token |
| `POST /api/v1/auth/refresh` | refresh token ← زوج جديد (**تدوير** — القديم بيتقفل). بياخد `companyId` اختياري = تبديل الشركة |
| `POST /api/v1/auth/logout` | يقفل الـ refresh token |
| `POST /api/v1/auth/change-password` | يتحقق من السياسة، يقفل كل الجلسات التانية، ويرجّع جلسة جديدة |
| `GET /api/v1/auth/me` | المستخدم + أدواره + صلاحيات الشاشات + الحقول المقيّدة + الشركات المتاحة |

**قواعد مهمة:**
- **اسم مستخدم غلط وكلمة مرور غلط بيرجعوا نفس الرسالة**، واسم المستخدم المش موجود بيعدّي على BCrypt برضه — عشان لا الرد ولا وقته يكشف مين موجود.
- **كل محاولة بتتسجّل** في `LoginAttempts` (حتى لو اسم المستخدم مش موجود).
- **القفل:** المحاولة رقم `MaxFailedLoginAttempts` (5) بتقفل الحساب `AccountLockoutMinutes` (15 دقيقة)، والقفل بيتفك لوحده بعد المدة أو بزرار "فك القفل".
- **تدوير الـ refresh token + كشف إعادة الاستخدام:** لو token قديم اتستخدم تاني (يعني حد تاني معاه نسخة)، **كل جلسات المستخدم بتتقفل**.
- **الـ refresh token متخزّن SHA-256 hash** — التوكن نفسه مابيتخزنش.
- **مدة الـ access token = `SessionTimeoutMinutes`** (30 دقيقة)، والفرونت بيجدّده لوحده عند أول 401 (طلب واحد مشترك حتى لو 10 طلبات فشلوا مع بعض).
- **"لازم يغيّر كلمة المرور"** (أول دخول، reset من الأدمن، أو انتهت `PasswordExpiryDays`): التوكن بيحمل علامة، والـ API **بيرفض أي حاجة** غير تغيير كلمة المرور و`/auth/me`.

## 3. صلاحيات الشاشات

**كل controller لازم يقول هو تبع أنهي شاشة** (`[Screen("CODE")]`) أو إنه مفتوح لأي حد داخل (`[AnySignedInUser]` — القائمة، المرفقات، مسميات الحقول، الدخول). **controller من غير الاتنين بيترفض** — وفيه اختبار بيتأكد إن كلهم متربطين، فأي controller جديد يتنسي هيوقع الاختبار.

**الصلاحية المطلوبة بتتحدد من نوع الطلب** (فلتر واحد عام، ترتيبه قبل الـ validation عشان اللي مالوش صلاحية ياخد 403 مش تفاصيل الفورم):

| الطلب | الصلاحية |
|---|---|
| `GET` | عرض |
| `POST` على الـ root | إضافة |
| `PUT` / أي `POST` تاني | تعديل |
| `DELETE` | حذف |
| `post` / `approve` / `reject` / `reverse` / `cancel` / `settle` / `reopen` / `award`… | **اعتماد** |

- **الاعتماد منفصل عن التعديل:** اللي بيجهّز فاتورة مش بالضرورة هو اللي يرحّلها. **كل اعتماد/رفض ناجح بيتسجّل** في سجل المراجعة.
- **البيانات المرجعية** (الأصناف، الحسابات، العملاء، الموردين، المخازن، الفروع، قوائم الأسعار، طرق الدفع، الإعدادات اللي شاشات تانية بتقراها…) **قراءتها مسموحة لأي حد داخل** — لأن شاشات تانية محتاجاها في القوايم المنسدلة (الكاشير محتاج يشوف الأصناف). **التعديل عليها محتاج صلاحية الشاشة.**
- **`SUPER_ADMIN` و`COMPANY_ADMIN` صلاحياتهم كاملة** ومابيتفحصوش. **باقي الأدوار الـ6 بتبدأ من غير أي صلاحية** — لازم تتحدد من شاشة الأدوار.
- **مدير النظام بس** اللي يدّي دور مدير النظام، ومحدش يقدر يشيل صلاحية الإدارة من نفسه أو يوقف حسابه.

## 4. صلاحيات الحقول الحساسة

| الكيان | الحقول | فين بيتطبّق |
|---|---|---|
| العميل | حد الائتمان · التليفون · الإيميل | شاشة العملاء |
| المورد | حد الائتمان · التليفون · الإيميل | شاشة الموردين |
| الوردية | النقدية المتوقعة عند الإقفال | شاشات الورديات |
| دفعة POS | مرجع عملية الكارت | الشيكات والفواتير |

- **الحقل من غير قيد = عادي.** القيد بيتعمل للدور من شاشة الأدوار (مقيّد ← عرض/تعديل/يتسجّل).
- **العرض مقفول:** الحقل بيرجع `null` في أي رد من الشاشة دي.
- **التعديل مقفول:** القيمة المتخزنة **مابتتغيرش** حتى لو الفورم بعت قيمة (مهم: الفورم أصلًا استلم الحقل فاضي، فلو اتحفظ عادي كان هيمسح القيمة).
- **الموظف والأصل الثابت** موجودين في القائمة لكن مالهمش كيانات لسه (HR والأصول الثابتة).

## 5. سجل المراجعة المركزي

- **كل إضافة وحذف وكل حقل اتغيّر** في أي كيان بيتسجّل تلقائيًا — **في نفس الـ transaction** بتاع التغيير (لو التغيير فشل، السجل مبيتكتبش، والعكس).
- **الحقول الحساسة وكلمة المرور** بتتسجّل `[REDACTED]` دايمًا. `RequiresAuditLog = false` على دور بيشيل تسجيل تعديل الحقل الحساس للدور ده (لو كل أدوار المستخدم قافلينه).
- **الدخول والخروج والاعتماد والرفض** بيتسجّلوا كأحداث.
- **مش متسجّل:** محاولات الدخول والـ refresh tokens (ليهم جداولهم)، وأعمدة الـ bookkeeping (`UpdatedAtUtc`…).
- السجل **append-only** — أي تعديل أو حذف بيترفض.

## 6. الشاشات

| الشاشة | المسار |
|---|---|
| تسجيل الدخول (مع اختيار الشركة لو المستخدم له أكتر من واحدة) | `/login` |
| تغيير كلمة المرور (إجباري أو اختياري من الشريط الجانبي) | `/change-password` |
| المستخدمون — البيانات، الأدوار في الشركة، **النطاقات (الشركات والفروع)**، reset كلمة المرور، فك القفل | `/settings/users` |
| الأدوار والصلاحيات — **مصفوفة صلاحيات الشاشات** (7 صلاحيات × كل الشاشات، بالمجموعة والصف والعمود) + **صلاحيات الحقول** | `/settings/roles` |
| الجلسات النشطة + إنهاء جلسة | `/settings/sessions` |
| محاولات الدخول (فلاتر + صفحات) | `/settings/login-attempts` |
| سجل المراجعة (فلاتر بالمستخدم/الكيان/السجل/العملية/التاريخ) | `/settings/audit-log` |
| إعدادات الأمان (كلمة المرور، القفل، الجلسات، الاحتفاظ) | `/settings/security` |

> الطلب كان 10 شاشات منفصلة. **"نطاقات المستخدمين" بقت جزء من شاشة المستخدم، و"صلاحيات الشاشات" و"صلاحيات الحقول" جزء من شاشة الدور** — بتتظبط وانت شايف الحاجة اللي بتظبطها، مش في شاشة تانية تدوّر فيها على المستخدم أو الدور من جديد.

**في الفرونت:**
- **القائمة الجانبية** مفلترة من السيرفر.
- **أي تاب لشاشة مالكش عليها صلاحية** بيعرض رسالة "مالكش صلاحية".
- **أزرار الـ ActionBar** (حفظ/ترحيل/حذف/طباعة) **وطباعة وتصدير الجداول** بتختفي حسب الصلاحية.

## 9. الاختبارات الجديدة (14)

`SecurityTests` (13): التوكن بيحمل الشركة والأدوار وبيتسجّل · الرد واحد للغلط والمش موجود · القفل في الخامسة وفكه · التدوير وكشف إعادة الاستخدام · الخروج · إجبار تغيير كلمة المرور · صلاحيات الشاشات + البيانات المرجعية · الاعتماد منفصل عن التعديل · القائمة المفلترة · **كل controller متربط بشاشة** · إخفاء الحقل وحمايته من التعديل · سجل المراجعة بالقيم المخفية · إنشاء مستخدم من الأدمن + مدير النظام بس يدّي مدير نظام.

`RealJwtTests` (1): تثبيت جديد ← `admin` يدخل بتوكن حقيقي ← صلاحيات كاملة، ومن غير توكن 401.

## 10. قبل ما تشغّل

1. **أعد تشغيل الـ API من Visual Studio** — النسخة الشغّالة دلوقتي قديمة.
2. **ادخل بـ `admin` / `Admin@123` وغيّر كلمة المرور فورًا** (من "تغيير كلمة المرور" في الشريط الجانبي).
3. **اعمل مستخدمين حقيقيين** وحدد صلاحيات الأدوار — الأدوار الـ6 غير الإدارية **فاضية**.
4. **الـ JWT Key في `appsettings.Development.json` للتطوير بس** — الإنتاج لازم يتحط له `Jwt:Key` سري.
