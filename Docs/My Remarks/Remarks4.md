## 2. معلومات إضافية معتمدة

### 2.1 البند 3 — زرار "حسابات تجريبية"

**قبل الحذف**:
1. ابحث في الكود عن `demoAccounts` أو ما يشابه.
2. حدّد: هل مربوط بـ Dev Login ولا Seed Data؟
3. لو Dev Login → احذف.
4. لو Seed Data → اتأكد مش مستخدم في أي مكان، وبعدين احذف.

### 2.2 البند 6 — إعدادات دورة المشتريات

**Claude Code يعمل الجرد بنفسه**:

**الخطوات**:
1. ابحث في الكود عن `PurchaseSettings` + كل `Setting`.
2. سجّل كل إعداد:
   - الاسم والنوع والافتراضي.
   - مكان الاستخدام (Backend / Frontend / الاثنين / لا شيء).
3. صنّف كل إعداد:
   - ✅ **مفعّل بالكامل**.
   - 🟡 **مفعّل جزئيًا**.
   - ❌ **غير مفعّل**.
4. فعّل الإعدادات غير المفعّلة:
   - ربطها بالكود.
   - إضافة اختبارات.
5. **تقرير** في `docs/Modules/Purchasing-Settings-Audit.md`:
   - قائمة كاملة بالإعدادات.
   - حالة كل إعداد.
   - اللي اتعمل لتفعيله.
   - اختبارات جديدة.

**الحجم**: 3-5 أيام (حسب عدد الإعدادات).

### 2.3 البند 7 — سداد الموردين

**الشاشة موجودة — نطوّرها**.

**الخطوات**:
1. **راجع الشاشة الحالية** — إيه اللي موجود وإيه اللي ناقص.
2. **Backend**:
   - `GetSupplierOutstandingInvoicesQuery` جديد.
   - `AllocatePaymentCommand` جديد.
   - تعديل `CreateSupplierPaymentCommand` ليشمل التوزيع.
   - التحقق من `PurchaseInvoice.PaidAmount` و `PaymentStatus`.
3. **Frontend**:
   - تعديل الشاشة الموجودة.
   - مكوّن جديد `InvoiceAllocationTable`.
   - عند اختيار المورد → جلب الفواتير.
   - عند كتابة المبلغ → توزيع FIFO افتراضيًا.
   - السماح بالتعديل اليدوي.
   - Validation: المجموع = المبلغ.
4. **Validation**:
   - `PUR-PAYMENT-EXCEEDS-OUTSTANDING`.
   - `PUR-PAYMENT-ALLOCATION-MISMATCH`.
5. **اختبارات** (5+).

**الحجم**: 3-4 أيام.

### 2.4 البند 8 — مردودات المشتريات

**الشاشة موجودة — نطوّرها**.

**⚠️ تحذير**: ده تغيير في الـ Domain — `PurchaseReturnLine` هيتغيّر.

**الخطوات**:
1. **Backend**:
   - إضافة `PurchaseReturnLine.PurchaseInvoiceLineId` (FK).
   - Migration لربط السطور الحالية (Best-effort).
   - `GetInvoiceLinesForReturnQuery` جديد.
   - تعديل `CreatePurchaseReturnCommand`.
2. **Frontend**:
   - تعديل الشاشة الموجودة.
   - عند اختيار الفاتورة → جلب سطورها.
   - منع إضافة أصناف جديدة.
   - الكمية محدودة بالكمية في الفاتورة.
   - زر "مردود كلي" (اختصار).
3. **Validation**:
   - `PUR-RETURN-EXCEEDS-INVOICE`.
   - `PUR-RETURN-NO-LINES`.
   - `PUR-RETURN-INVALID-ITEM`.
4. **اختبارات** (5+).

**الـ Migration Strategy**:
1. إضافة `PurchaseInvoiceLineId` (nullable).
2. تعبئة البيانات:
   - لو `PurchaseReturn` مرتبط بـ `PurchaseInvoiceId`:
     - حاول ربط السطور بنفس `ItemId`.
     - Best-effort: لو تطابق وحيد، اربط.
     - لو مش وحيد، سيبها `nullable`.
3. السطور اللي مش قابلة للربط → تفضل `nullable`.
4. **تحذير**: المرتجعات القديمة ممكن تكون فيها سطور مش قابلة للربط.

**الحجم**: 3-4 أيام.
